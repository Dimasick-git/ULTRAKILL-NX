Движок сообщает около 373 МБ used для ALLOC_DEFAULT и 720 МБ для

теперь вместо повреждения выявилась настоящая нехватка доступного backing.

## Изменение схемы памяти

Форвардер теперь задаёт `address_space_type=3` (39-битное пространство)
и `system_resource_size=0x02000000` (32 МБ) в NPDM. Разрешения
svcMapPhysicalMemory/svcUnmapPhysicalMemory уже были в списке.
Ненулевой служебный резерв требуется самим ядром:
[Atmosphère, MapPhysicalMemory](https://github.com/Atmosphere-NX/Atmosphere/blob/master/libraries/libmesosphere/source/svc/kern_svc_physical_memory.cpp).
Формат поля подтверждается
[npdmtool](https://github.com/switchbrew/switch-tools/blob/master/src/npdmtool.c).

Загрузчик до инициализации malloc:

1. Проверяет служебный резерв, права SVC и свободное Alias-окно 6 ГБ.
2. Сохраняет начальную часть кучи hbloader, из которой отображён NRO,
   оставляет 608 МБ для newlib и 160 МБ для модулей движка.
3. Уменьшает физическую кучу; проверяет Map/Unmap на одной странице.
   Если проба не проходит, восстанавливает прежний размер кучи.
4. Резервирует Alias-окно в virtmem и выделяет физические страницы только
   при mmap с доступом или при mprotect. PROT_NONE не занимает physical backing.

При этом больше не выделяются физическая mmap-арена 1792 МБ и запасной
640-МБ пул отображений в стек. Прежние функции backed-режима сохранены
для отката настройки, но r15 не запускает движок без успешного demand-memory:
показывает сообщение об обновлении форвардера вместо очередного чёрного экрана.
В логе печатаются Program ID, SystemResource, результаты heap resize и probe.

Ошибки физического commit теперь возвращаются вызывающему коду; не выдаётся
успех для страницы, которая не была отображена. При неудачном mmap уже
выделенные страницы освобождаются, виртуальная резервация снимается.

## Обязательный шаг на консоли

Установить через DBI **новый** `E:/ULTRAKILL_NX_forwarder.nsp`, заменив
прежний форвардер этого Title ID. Затем запустить **ULTRAKILL NX с HOME**.
Одна замена NRO не меняет настройки уже установленного процесса.

Признаки правильного запуска в новом debug.log:

```
demand-memory-r15
launch process=01005ce3b1a40000 system_resource=32 MB demand_memory=1
OVERCOMMIT on
```

Общий лимит физической памяти консоли не увеличивается. Переход устраняет
предварительное занятие неиспользуемых резервов. Запуск сцен, изображение,
звук, управление и дальнейшее потребление памяти требуют проверки на Switch.
