# Проверки и известные ограничения

## Что подтверждено

- Host GCC: настоящий код CPU affinity, dladdr, GC bridge и агрегации ошибок.
- Input System в Unity: 14 цифровых кнопок, оси курков, реальные UI actions,
  совместные нажатия, отпускание, физические A/B и названия кнопок.
- OpenGL ES 3 в редакторе: два GPU-прохода FSR, ориентация и цвета квадрантов.
- Android Export: errors=0. IL2CPP: 350 успешных nodes при добавлении FSR.
- Устройство r26: EASU+RCAS активны после перехода сцены; GC disabled=0,
  native_stw=1; маска процесса 0x7, три разрешённых ядра.
- r27 на устройстве: агрегация сохраняет счётчик и выводит сводки; переход 1-1 → 1-2
  выявил native NULL-dereference в Umbra Tome::getStatus, подтверждённый crash report.
- r28: null-safe guard, host-тест valid/invalid/init NULL, NRO и IL2CPP собраны.
  Новый native callback снимает ограниченные образцы до unwinding NRE.
- Аппаратная проверка перехода Лимбо с r28 ещё нужна.

## Последний аппаратный прогон r26

Зарегистрировано 8096 сообщений исключений, преимущественно NullReferenceException,
без полезного стека. Их источник остаётся неизвестным; близость обращений
к unity.cloud_userid не доказывает причину. r27 сохраняет первые четыре одинаковых
сообщения, затем повторяет образец и сводку раз в 5 секунд. Новая ошибка пишется сразу;
общий счётчик не уменьшается. Это уменьшает вывод на SD, но не частоту исключений.

В конце игры встречаются интервалы 40–54 FPS, паузы до 392 мс. Загрузки сцены
могут длиться десятки секунд. UnityMain потребляет около 77–87% ёмкости одного ядра;
Gfx и два Job.Worker используют разрешённую маску 0x7. Эти данные не измеряют
загрузку GPU и не доказывают конкретный источник каждой паузы.

## Перед следующей публикацией

1. Запуск с HOME, меню A/B, независимость ZL/ZR, обе оси гироскопа.
2. Видео со звуком, вход на уровень, HUD и переходы с FSR; проверить fallback.
3. Повтор одного маршрута с одинаковыми частотами: FSR off/on и 540p/480p.
4. 30–60 минут, перезапуски и переходы: used/heap, stw_passes, crash report.
5. Новая распаковка двух ZIP в обоих порядках: без недостающих файлов,
   совпадающие общие README/SHA256SUMS, проверка каждого файла по манифесту.

Новые заявления о производительности должны сопровождаться сопоставимыми
журналами. Host/редактор не подтверждают полное прохождение на Switch.
