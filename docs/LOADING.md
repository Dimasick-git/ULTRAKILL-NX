# CPU FastLoad

r32 запрашивает штатный Horizon FastLoad через appletSetCpuBoostMode.
CPU получает запрос буста, GPU переводится в минимальный режим. Поэтому
режим используется только для начальной загрузки библиотек и загрузок сцен.
Конкретные частоты не задаются: результат зависит от Horizon и настроек RCU.
RC syscall=0 подтверждает принятие запроса, а не измеренную частоту CPU.

Native worker снимает запрос по таймеру 60 секунд и при потере фокуса.
NxLoadingBoost завершает начальный буст и устанавливает SceneManagerAPI,
который охватывает синхронный/асинхронный запуск Single-загрузки.
Additive-стриминг обходится без буста, поскольку может идти во время боя. Режим снимается
при sceneLoaded, завершении AsyncOperation, исключении, HOME/потере фокуса,
выключении компонента и обычном выходе. Установка Normal выполняется
синхронно до возврата из обработчика sceneLoaded, без ожидания worker.
Если другой пакет уже владеет SceneManagerAPI.overrideAPI, его API сохраняется:
перехват последующих загрузок не ставится, это отражается в журнале.

Worker создаётся до включения буста; если создать или запустить его нельзя,
feature выключается. При отказе сброса active не помечается ложным: таймер
повторяет восстановление каждые 50 мс, в том числе при сохранённом фокусе,
не дожидаясь timeout; повторные сообщения об отказе ограничены. Доступ к запросам сериализован mutex.
Новые загрузки не продлевают уже активный 60-секундный timeout.

config.txt: loading_boost 1 (default), loading_boost 0 — выключить.
Лог: [loading-boost] FastLoad request / restore normal / timeout/focus restore
с настоящим Result. Нужна проверка частот и переходов на устройстве.
Профиль разгона пользователя, память, напряжения и тайминги не изменяются.
