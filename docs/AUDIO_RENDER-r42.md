# r42: остановка аудиопотока и привязки камер

Новый лог r41: `r41-audio-render-feedback/debug.log` (копия с карты).
После вступления callbacks перестаёт меняться на 2448. Mute=0, volume=0mB,
queued=15. Это не доказательство исправного звука: SDL callback уже не работает.
Отдельный PC аудиопотока в старом логе не снят; точный стек остановки неизвестен.

Сверен именно связанный r41 SDL ELF: SWITCHAUDIO_PlayDevice содержит цикл
`while (state != Playing)`. Если планировщик задержит поток до Done, этот цикл
не завершится. Также исходная ветка могла обращаться к buffer[-1], если ни
один буфер не наблюдается Playing. Исправления громкости r41 не устранили
эти ошибки драйвера.

## Звук

`loader/source/nx_sdl_audio.c` заменяет bootstrap статического SDL 2.28.5.
Оригинальный объект SWITCHAUDIO_PlayDevice больше не связан; это проверено nm.
Private ABI заголовков закреплён на devkitPro/SDL
0738d3c9f6993875e2f3dd0e8cc0bb4ae4440b4e, с compile-time проверкой версии и
смещения hidden. При обновлении SDL адаптер требует повторной сверки.

Буфер разрешено перезаписать только после Free/Done. Переход через Playing
наблюдать не требуется. Ожидание ограничено 20 событиями по 5мс, проверяет
shutdown и ошибки audrvUpdate. При отсутствии свободного буфера данные в
полёте не перезаписываются. Подробности ошибки пишутся как [audio-driver].
Исправлены лишнее выделение buffer_tmp и освобождение pool при закрытии.
Громкость/mute из r41 сохранены. Диагностика дополнена SDL device status.

`test_sdl_audio_pacing.py` компилирует реальные функции backend и моделирует
Queued→Done без наблюдения Playing, полную очередь, освобождение второго
буфера, shutdown и ошибку IPC. Это воспроизведение опасного пути, а не
аппаратное подтверждение причины конкретного запуска.

## Изображение

`patch_world_mrt.py` после Android export добавляет повторную привязку трёх
world MRT и depth после SetupRTs в world-ветке OnPreRenderCallback. Ранее
SetTargetBuffers выполнялся при пересоздании RT, а живые ссылки/размеры не
подтверждали сохранение native binding. Текстуры и разрешение каждый кадр
не пересоздаются. Это исправление пути привязки; визуальное подтверждение
на Switch ещё требуется.

Применить `python tools/patch_world_mrt.py <generated>/Assembly-CSharp__23.cpp`
до compile-cpp. Изменён один generated C++ файл, managed metadata и шаг физики
не меняются. `test_world_mrt.py` компилирует вставляемый код и проверяет
100 потерь/восстановлений привязок, отсутствие аллокаций и проверки границ.

Приёмка на Switch: звук меню/уровня/после перехода, изображение при первом
запуске и после загрузки без изменения Ryazha-clk, пауза/продолжение.
Результаты пока не получены. Генерация кадров не входит в r42.
