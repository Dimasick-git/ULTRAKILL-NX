# r19 — корректность времени и профиль производительности

Пользователь подтвердил высокий FPS в обучении, низкий FPS в обычных уровнях,
ускоренное движение и долгие/зависшие загрузки. Это ещё не достижение 60 FPS.
До обновления скопирован debug.log с карты в uk-build/debug-run18.log.
Предыдущие NRO, offsets, config и личные настройки сохранены в backup-run18.

## Время

Удалены заплатки управляемых Time.deltaTime/frameCount/realtimeSinceStartup.
Нативный TimeManager уже восстановлен и продвигается, что подтверждено логом.
Прежняя подмена deltaTime не учитывала контекст FixedUpdate: на медленном
кадре возвращала длительность всего кадра вместо физического шага. Это
ошибка независимо от того, объясняет ли она все жалобы на скорость.

Фоновая помощь часам теперь разрешена только до первого штатного вызова
TimeManager::Update. После этого медленный кадр не приводит к параллельному
изменению времени движка из постороннего потока. Снятие зависаний загрузки
после этого изменения ещё требует проверки на Switch.

Диагностика fixedDt теперь читает настоящий getter; прежнее чтение float
из непроверенного смещения +0xd8 показывало 0 и было недостоверно.

## Нагрузка

- performance_mode=1: запрос Screen.SetResolution 960x540 с программным
  масштабированием. Настоящее NWindow не уменьшается: его изменение ранее
  приводило к зависшему выводу. По сравнению с 1280x720 это на 43,75% меньше
  пикселей внутреннего рендера, если движок применит запрос.
- GlobalTextureMipmapLimit=1: для поддерживающих mipmapping текстур пропускается
  верхний mip; это уменьшает загружаемые размеры, без изменения исходных бандлов.
- Отключены MSAA и динамические тени штатными QualitySettings.
- Целевой FPS 60. LocalPrefs.frameRateLimit=3 подтверждён исходным IL2CPP
  GraphicsSettings.SetFrameRateLimit. Прежнее значение 7 означало 288.
- maxGore уменьшен с 3200 до 256. Прочие личные настройки сохранены.
- shader_chunks увеличен с 4 до 16: кэш Master ограничен примерно 256 MiB,
  а не 64 MiB. Это сохраняет конечный лимит памяти и должно уменьшить повторную
  распаковку блоков. Аппаратный эффект пока не измерен.
- debugPrintf больше не делает SD fflush на каждой строке: интервал до секунды,
  ошибки выделения памяти/abort/watchdog сбрасываются сразу. После аварии может
  потеряться последний буфер обычного журнала.
- Буферы форматирования Android log теперь локальны для вызова, без гонки
  общего статического буфера между потоками.

## Замеры и оставшаяся проблема

Каждые пять секунд eglSwapBuffers записывает [perf]: настоящий present FPS,
среднюю длительность, p95, худший кадр, ожидание swap и число draw calls.
Это CPU/представление кадра, не отдельный GPU-профайлер. Для первых четырёх
исключений запрошен Full stack trace, затем полные обходы отключаются, чтобы
не превратить диагностику в постоянную нагрузку. Счётчик исключений сохраняется.
Повторяющиеся NullReferenceException пока не исправлены: нужен новый стек.

## Проверка

devkitA64 собрал NRO. Реальный nx_perf.c прошёл host-проверку 60/20 FPS,
p95 16,67/50 мс и swap 2 мс. Тесты demand-memory и mmap fallback прошли.
Проверка ARM64 accessor кэша шейдеров прошла. Новые адреса QualitySettings,
Screen.SetResolution и Application получены из символов с тем же build-id.
NRO, config и offsets записаны на карту и побайтово сверены со staging.

Нужен прогон обычного уровня на Switch минимум минуту и новый debug.log.
Стабильные 60 FPS, исправленная скорость и ускоренные загрузки не подтверждены.
NSP переустанавливать не нужно; опубликованный r1 пока остаётся прежней сборкой.
