# r17 — ограничение распакованного кэша шейдеров

Аппаратный запуск r16 состоялся: NRO r15 включил demand-memory, движок
продолжал кадры Bootstrap, но закончился `System out of memory`.
Журнал сохранён в `uk-build/debug-run16.log`, предыдущие файлы карты —
в `uk-build/backup-run16/`.

Перед вылетом физически выделено 2453 МБ. ALLOC_CACHEOBJECTS занимает
1 993 652 930 байт; неудачное выделение Serialization — 16 753 056 байт,
то есть очередной распакованный блок шейдера. Master содержит 70 544 блоба
общим несжатым размером 1910 МБ; параметры занимают только 20 976 240 байт
и находятся в первых двух блоках. Стереоключи есть в таблице имён, но
активных вариантов с ними нет, поэтому их удаление ничего не экономит.

## Исправление

После init_array и до первого входа в движок вызывается настоящий
`Shader::SetMaxChunksRuntimeOverride(4)`, затем getter проверяет результат.
Это штатный API `Shader.maximumChunksOverride`. При нуле Unity распаковывает
все блоки, при положительном числе использует ограниченный кэш.
Все программы и эффекты сохранены. Ожидаемый предел распакованных блоков
Master — около 64 МБ; метаданные, параметры и GPU-программы учитываются отдельно.

В этой libunity `Shader::Transfer<StreamedBinaryRead>` читает глобальный
override непосредственно (0x17cd558), передаёт его в ShaderBinaryData::SetData
с options=2. При нуле SetData распаковывает все сегменты; положительный
лимит меньше числа сегментов включает вытеснение и первоначально распаковывает
только таблицу. Поэтому подмена одного getter не помогла бы: вызывается setter.

Адреса обоих методов добавлены в генератор unity_syms.py и offsets.ini.
Без адресов загрузчик останавливается с понятным сообщением, чтобы устаревший
offsets.ini не позволил снова незаметно загрузить все шейдеры.

## Проверка и карта

- `validate_shader_cache.py` проверил совпадение build-id, реальные ARM64
  инструкции setter/getter, общий writable int и исходное значение -1.
- devkitA64 успешно собрал NRO.
- NRO и offsets.ini записаны в staging и `E:\switch\ultrakill`, SHA-256 совпали.
- NRO: `2234b84e0a302bf11316b4cfec3eaca2373b7aae3c798d29bbf60a4ebdbe5ef3`.
- offsets.ini: `4c1e0057425755a40496f4bbaadd8c46a93e2a4328a0b10f2411048c96f0aaca`.

NSP остаётся r16, переустанавливать через DBI не нужно. Запуск с HOME.
Маркеры следующего журнала: `shader-cache-r17` и
`[shader-cache] maximumChunksOverride -1 -> 4`.

Работа изображения, звука и перехода в Tutorial после исправления ещё
требует аппаратного запуска. Успешной сборки недостаточно для такого вывода.

API Unity: https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Shader-maximumChunksOverride.html
