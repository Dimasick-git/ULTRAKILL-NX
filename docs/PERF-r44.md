# r44 / TEST8: FPS и отправка кадров

Источник: запуск r43 в `uk-build/r43-fps-feedback/debug.log`, последний boot
marker r43 начинается со строки 54363. Предыдущие запуски в том же файле
не используются для оценки TEST7.

В r43 создаются сессии FG (`capture enabled`), но нет ни разрешения
`nxb_fg_enqueue`, ни native `graph ready`/`completed frame`. Поэтому считать
FG реально работавшей в этом запуске нельзя. Перед enqueue стоял managed
барьер `worldFrame == Time.frameCount`, зависящий от порядка camera callbacks.
Он удалён. Готовность теперь отмечается plugin event 13 после GPU-команд
копирования глубины/движения; событие 11 потребляет только новую отметку.
Повторная композиция без нового world capture не интерполирует старые данные.
При отсутствии отметки native пишет явный `waiting for world capture marker`.
Это позволит отличить проблему GPU capture от metadata/dispatch/present.

Host test запускает реальный production capture state: 1000 вложенных
композиций до managed onPostRender, отклонение дубликатов/пустых кадров,
несколько world draws и сброс состояния сцены. Проверка проходит.

В конце запуска r43 реальные настройки дошли до 1280×720; до этого были
320×180, 448×252, 704×396 и другие ступени внешнего ползунка. Последние
окна FPS — примерно 33–40, UnityMain занят 79–85% одного ядра и закреплён
на CPU 0. Gfx worker и два Job.Worker имеют mask 0x7, то есть могут конкурировать
с ним. Auto aim targeter занимает около 2.1–2.5 ms/update; это часть нагрузки,
а не доказательство причины всего оставшегося времени кадра. Автоприцел
не отключён и не замедлен.

r44 ограничивает только UnityGfxDeviceWorker и foreground Job.Worker маской
разрешённых процессу ядер без CPU 0. На этом Switch это 0x6; системное ядро
не запрашивается. Прочие потоки, приоритеты и физика не меняются. Если нет
другого разрешённого ядра, политика ничего не меняет. Явные последующие
запросы affinity движка продолжают работать. Host test проверяет обычную,
разреженную и одноядерную маски, ошибки ядра и сохранение UnityMain/FMОD.

Проверка на консоли ещё нужна: native `graph ready` и `completed frame`,
стоимость compute+transfer, actual worker affinity и тот же бой при 540p
и 720p. Сравнение разных сцен и средних FPS с включённой загрузкой не годится
для доказательства ускорения. Значения fixedDt=0.008, timeScale=1.00 и
exceptions=0 в r43 сохранены. Причина прежнего menu crash пока не доказана.
