# r23 — проверка исправления памяти

В [issue #1](https://github.com/Dimasick-git/ULTRAKILL-NX/issues/1) сообщается
о вылете при перезапуске. В приложенном журнале r22 физическая память mmap
растёт до 2466 МБ; при загрузке Level 0-3 не удаётся добавить ещё 4 МБ.
Сразу после этой записи начинается другой запуск процесса.

В r22 загрузчик отключал GC после старта: это было обходом неработающей доставки
POSIX-сигналов на Horizon. Старый мост только подтверждал сигналы, не останавливая
потоки и не сохраняя живые ссылки в регистрах. Включать GC с таким мостом нельзя.
Отключение коллектора — подтверждённая причина накопления управляемого мусора;
это не доказывает отсутствие других источников роста памяти.

## Что меняет r23

- `nx_gc.c` действительно останавливает зарегистрированные потоки через Horizon,
  получает SP и регистры, затем возобновляет потоки после маркировки.
- Патч Boehm передаёт сохранённый SP в его собственную запись потока и добавляет
  полный регистровый контекст как корни, включая LR и NEON. Живые ссылки,
  оставшиеся только в регистрах, учитываются.
- Сохраняется штатный список потоков и протокол подтверждений Boehm. Смещения
  внутренних полей GC не угадываются: их использует код той же библиотеки.
- Паузы GC и снимки watchdog разделяют один замок: сторож не может возобновить
  поток посреди сборки мусора.
- При ошибке остановки/контекста уже остановленные потоки возобновляются;
  ошибка передаётся коллектору вместо ложного подтверждения.
- С новым backend загрузчик оставляет автоматическую сборку включённой.
  Старый IL2CPP распознаётся и остаётся с отключённым GC, с ошибкой в журнале.
- `[gc]` показывает `used`, `heap`, `disabled`, `native_stw` и `stw_passes`.
  Последнее — число проходов остановки, не число законченных полных сборок.

## Сборка

После Android Export, перед compile-cpp, выполнить:

```sh
python tools/patch_gc_horizon.py path/to/IL2CPP/external/bdwgc/pthread_stop_world.c
```

Скрипт сохраняет исходные лицензионные уведомления и резервную копию, проверяет
точное наличие всех якорей и не дублирует уже применённый патч. На обычном Android
без nxbridge остаётся стандартная доставка сигналов. Нужен **новый IL2CPP вместе
с новым NRO и заново выведенными offsets**. Метаданные r22/r23 совпадают.

## Проверки

Нативная библиотека и загрузчик собираются. Host-тест компилирует настоящий
`nx_gc.c` с адаптером ядра: SP, корни только в регистрах, пауза/возобновление,
повторная остановка, запрет снимков watchdog, неизвестный поток, отказ SVC,
нечитаемый стек и заполнение таблицы — PASS. Проверка обходчика стеков с
защищёнными страницами также проходит.

Это **не заменяет проверку на Switch**. Восстановление режима GC — существенное
изменение; устранение вылета на консоли пока не подтверждено.

## Как проверить

На установленный полный r1 распаковать актуальный `ULTRAKILL_NX_r24_update.zip` в корень
карты с заменой папки `switch`. NSP, Saves и Preferences менять не нужно.
В архив включены согласованные NRO, библиотека, offsets и метаданные.

Проверить запуск, несколько перезапусков уровня и переходы после 20–30 минут игры.
Ожидаемые флаги: `native_stw=1`, `disabled=0`; `stw_passes` должен увеличиваться.
Нужен полный журнал, чтобы сравнить `used/heap` на повторных загрузках.
При сбое приложить свежий crash report. Issue остаётся открытым до такой проверки.

Перед обновлением сохрани прежние NRO, libil2cpp.so, offsets.ini и обе копии
global-metadata.dat: это резервная копия для отката. Полные ZIP r1 также содержат
этот backend GC (начиная с r23); маленький архив позволяет
обновить уже установленную игру без повторного скачивания всех данных.
