# Сборка мусора на Horizon

В issue #1 журнал r22 показал рост физической mmap-памяти до 2466 МБ и отказ
выделения следующих 4 МБ при загрузке Level 0-3. В r22 GC был выключен после старта:
POSIX-доставка сигналов на Horizon не обеспечивала безопасную остановку потоков.

## Исправление режима

В r23 добавлен настоящий Horizon backend остановки потоков, однако в r23/r24
загрузчик ошибочно передавал режим 0. В API этой Unity `DISABLED=0`, `ENABLED=1`.
Поэтому утверждение ранних описаний о включённом GC в r23/r24 было неверным.
С r25 передаётся **1**, затем проверяется `il2cpp_gc_is_disabled`. Несовместимый
backend или выключенный коллектор приводят к явному отказу запуска.

Журналы r25/r26 подтверждают `disabled=0`, `native_stw=1` и рост `stw_passes`.
В конце последнего прогона r26 managed heap 91 МБ, used 67 МБ. Это managed-память,
а не вся память процесса; отсутствие других утечек и длительная стабильность не доказаны.

## Backend

`nx_gc.c` останавливает зарегистрированные потоки через Horizon, получает SP
и полный контекст, включая LR и NEON. Boehm получает стек и корни регистров.
Его штатный список потоков и протокол подтверждений сохраняются. Общий gate
не позволяет watchdog возобновить поток во время сборки. Ошибки остановки
возвращаются коллектору с возобновлением уже остановленных потоков.

После Android Export, перед compile-cpp:

```sh
python tools/patch_gc_horizon.py path/to/IL2CPP/external/bdwgc/pthread_stop_world.c
```

Патч проверяет якоря, сохраняет оригинал и лицензию, повторное применение безопасно.
На Android без nxbridge сохраняется обычная доставка сигналов.
Библиотека, offsets и обе metadata должны принадлежать одной генерации.

## Проверка

`test_gc_bridge.py` компилирует настоящий C-backend с адаптером ядра: регистровые
корни, остановка/возобновление, отказы SVC, неверный стек, заполнение таблицы и
взаимное исключение с watchdog. На Switch нужны повторные загрузки и перезапуски
после 30–60 минут, полный журнал used/heap и crash report при сбое.
`stw_passes` считает проходы остановки, а не завершённые полные коллекции.
Issue #1 остаётся открытым до длительной проверки.
