# Работа над проектом

Изменения оформляй отдельной веткой и небольшим PR. В описании укажи проблему,
изменённое поведение и проверки. Код платформы, managed-слой и инструменты
подготовки данных проверяй отдельно.

Для багов приложи сборку, шаги воспроизведения, журнал и окружение. Сборка сама
по себе не подтверждает исправление. Проблемы памяти проверяй длительным прогоном,
производительность — на одинаковом маршруте и профиле частот.

## Проверки

```sh
python tools/test_cpu_affinity.py --cc gcc
python tools/test_dladdr.py --cc gcc
python tools/test_gc_bridge.py --cc gcc
python tools/test_log_repeat.py --cc gcc
python tools/test_umbra_guard.py --cc gcc
python tools/test_salty_bridge.py --cc gcc
```

CI выполняет эти host-проверки. Изменение Unity дополнительно требует Input System
проверок, Android Export и GPU-пробы при изменении FSR. Сборка загрузчика и проверка
на устройстве документируются отдельно; CI не выдаёт их за выполненные.

## Выпуск

1. Собрать комплект и манифест SHA-256; проверить build-id и offsets.
2. Сохранить старые файлы и журнал устройства. Проверить обновление самой ранней r1.
3. Обновить CHANGELOG, README и INSTALL_RU; непроверенные части отметить отдельно.
4. Загрузить проверенный update ZIP во временные assets релиза и сверить SHA-256.
5. Workflow проверяет исходные архивы, накладывает обновление и создаёт два ZIP
   меньше 2 ГиБ. Старые assets удаляются только после проверки новых.
6. Скачать опубликованные ZIP и проверить их хеши и полную распаковку. Сохранить
   локальный полный архив и обновление, исходный commit и отчёт упаковки.

Секреты, ключи, сохранения, журналы пользователей, игровые бинарники и оригинальный
Unity-проект не коммитятся. При несовпадении хешей публикация останавливается.
