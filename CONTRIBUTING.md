# Работа над проектом

Изменения оформляются отдельными ветками и небольшими PR. В описании:
проблема, новое поведение, проверки и оставшиеся ограничения. Код платформы,
managed-слой и подготовка данных проверяются на своей границе совместимости.

Для багов нужны сборка, воспроизведение, журнал и окружение. Ошибку не закрываем
только потому, что код собрался. Проблемы памяти требуют длительного прогона;
производительность — одинаковых маршрута, частот и настроек.

## Проверки

```sh
python tools/test_cpu_affinity.py --cc gcc
python tools/test_dladdr.py --cc gcc
python tools/test_gc_bridge.py --cc gcc
python tools/test_log_repeat.py --cc gcc
python tools/test_umbra_guard.py --cc gcc
python tools/test_salty_bridge.py --cc gcc
```

CI выполняет эти host-проверки. Изменение Unity дополнительно требует Input System
проверок, Android Export и GPU-пробы при изменении FSR. Сборка загрузчика и проверка
на устройстве документируются отдельно; CI не выдаёт их за выполненные.

## Выпуск

1. Сформировать согласованный комплект и манифест SHA-256; проверить build-id и offsets.
2. Сохранить старые файлы и журнал устройства. Проверить обновление самой ранней r1.
3. Обновить CHANGELOG, README, INSTALL_RU и честно перечислить непроверенное.
4. Загрузить проверенный update ZIP во временные assets релиза, дождаться завершения
   и сверить серверный SHA-256. Только затем запускать Repackage full release.
5. Workflow проверяет исходные архивы, накладывает обновление, упаковывает два ZIP
   меньше 2 ГиБ и проверяет каждый файл. Старые assets удаляются только после
   проверки загрузки обоих новых. В итоге остаются PART_1 и PART_2, обычный релиз.
6. Скачать опубликованные ZIP и проверить их хеши и полную распаковку. Сохранить
   локальный полный архив и обновление, исходный commit и отчёт упаковки.

Секреты, ключи, сохранения, журналы пользователей, игровые бинарники и оригинальный
Unity-проект не коммитятся. При несовпадении хешей публикация останавливается.
